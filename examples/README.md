These six consecutive runs include the historical-benchmark and cost-share method, explicit comparison-category handling, calendar-based ABS/StatCan YoY decoders, common-period comparison and sentence-boundary parsing correction. They ran against Zetaris in Docker, NVIDIA Nemotron 3.5 Lightning through Meterless Nightshift, and a fresh H-MEM store. The first run also used a fresh Zetaris suffix, `night1027c12`; later runs reused what earlier runs left behind. This was a new set of application tables and views, not an empty Zetaris installation. Model calls appear in the traces as `openrouter/nvidia/nemotron-3.5-lightning via Meterless Nightshift`: the Nightshift lane forwards to NVIDIA Nemotron on OpenRouter. These recordings predate Zetaris `CACHE TABLE`, the schemastore comparison view, sentence-level narrative salvage and the "How far" line.

Each folder contains the actual `brief.md`, `trace.json` (model and agent events plus SQL statements, row counts and timings), `recording.json` (UTC recording time, CLI elapsed seconds, exit code and namespace), and `evidence.json` (versioned calculation inputs, raw SQL results and derived outputs). Raw briefs and traces are not edited to improve their outcomes. Timing includes CLI startup; “numbers” is the agent's measured time to the first market result. The separate evidence packet retains unrounded market and pricing rows, actual column metadata and the calculation time. All six packets passed `npm run verify -- <folder>/evidence.json`: 2,343 checks, 368 market rows and 417 pricing rows.

**Cost-timing limitation of these recordings:** examples 01, 02 and 05 use the before-change cost-share formula and produce a 3.4% target. The questions state the share in the present tense after a past rise ("costs rose 8%, unit costs are 60%"); today's code reads that as after-change and gives 3.1%, which would put example 05's cost target inside Australia's 3.0–3.2% benchmark. Current code distinguishes those bases and labels unspecified timing as an assumption. These recordings and their evidence packets remain unchanged; the subsequent cost-timing and input-boundary changes were tested offline. Offline replay validates the recorded calculation, not the interpretation of the original question.

**Calculation version:** these preserved packets use method 2. The verifier replays that version and warns about its historical all-items fallback. Current method 3 withholds requested-category comparisons when only all-items data is available, while keeping a valid cost target independent of market coverage. Every requested category in these six supported-market results had evidence, so their recorded market comparisons remain unchanged. This boundary fix and explicit “from 70% to 50%” field changes were verified offline.

**Known narrative error in example 06:** the Watch sentence says “the current HICP series appears discontinued.” Its query actually uses the successor `prc_hicp_minr`, with September 2026 observations. The discovery notes identify the older `prc_hicp_manr` as discontinued. Numeric and comparison checks accepted the sentence despite this inaccurate description of the source status. Do not present it as a correct explanation of the migration. The original brief remains unchanged.

Example 01 shows successful model selection: German gochujang uses the condiment series; German chips use a broader Food proxy; Australian condiments and snacks use their selected series; Canadian narrow categories use broader Food proxies. These choices are validated and remembered, not guaranteed exact product matches. The Canadian adapter only supports Food and All-items vectors. A supported request category such as snacks can therefore have broader Food evidence.

The common-period table uses August 2026 for the DE/CA/AU and CA/AU comparisons, and September 2026 for FR/IT/ES. Latest market cards keep each market's latest available period. Aligning dates does not make national baskets or categories identical.

**Verification scope:** the offline command checks that saved rows reproduce market means, counts, benchmarks, cost comparisons, common-period alignment and recorded SKU price arithmetic. It preserves Japan as unsupported in example 04: two markets requested, one verified. Example 06 has no pricing evidence and verifies no SKUs. Verification does not authenticate the agency/database response, replay the source index-to-YoY decoder, assess product-category fit, or prove the full meaning of model prose. Consistent changes to both rows and results can still pass. Numeric checks are not a guarantee of complete semantic correctness. Earlier recordings remain unchanged in Git history and local backups.
